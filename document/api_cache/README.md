# 공공 API 응답 캐시

실거래가(아파트·오피스텔·연립다세대), 건축HUB 건축물대장, 도로명주소(JUSO) 응답을 SQLite에 저장해서 같은 조회는 다시 부르지 않습니다.

- 목적: 개발계정 일일 호출 한도 절약, 시연 중 API 지연·장애 대비
- 팀 합의 방향(원본 → 정규화 → 집계, 캐시는 get/save로 감싸 SQLite 먼저)에 맞춰 `ApiCache`(get/save) 인터페이스와 SQLite 기본 구현을 둡니다. 서버 DB로 바꿀 때는 이 모양만 맞추면 됩니다.

## 동작

| API | 저장하는 것 | 캐시 키 | 만료 |
| --- | --- | --- | --- |
| 실거래가 | 해제 거래를 뺀 정규화 거래 목록 | 유형 + 시군구 5자리 + 연월 | 이번 달 1일, 지난 달 3일, 그 이전 90일 |
| 건축물대장 | 성공한 원본 XML | 기능 + 조회 조건(인증키 제외) | 30일 |
| 도로명주소 | 검색 결과 (전체 건수, 주소 목록) | 공백 정리한 검색어 | 30일 |

- 실거래가 API는 법정동이 아니라 시군구 단위로 조회합니다. 그래서 같은 시군구·같은 달이면 법정동이 달라도 한 번만 부릅니다.
- 실거래 신고 기한이 계약 후 30일이라 지난 달 거래도 한동안 늘어납니다. 그래서 지난 달은 짧게 둡니다. 해제 거래가 반영되도록 오래된 달도 무기한으로 두지 않습니다.
- 정상 응답만 저장합니다. 오류 응답(인증키 오류, 한도 초과 등)은 저장하지 않습니다.
- API가 실패(연결 오류, 시간 초과, 5xx, 인증키 오류·키 없음, 응답 해석 실패)했는데 만료된 지 30일 안의 저장본이 있으면 그것으로 응답하고 경고 로그를 남깁니다. 인증키가 빠지거나 만료돼도 모르고 지나가지 않게 하려는 것입니다. 주소 검색어 오류는 저장본으로 덮지 않습니다.
- 저장본이 만료된 지 30일을 넘으면 쓰지 않고 실패(`API_UNAVAILABLE`)로 둡니다. 오래된 시세로 등급을 내지 않게 하려는 것입니다.
- 만료된 지 30일이 지난 행은 지웁니다. 캐시를 열 때와, 저장할 때 한 시간에 한 번 정리합니다. 주소 캐시에는 사용자가 입력한 주소가 들어 있어서 저장 후 최대 60일(만료 30일 + 30일)까지만 남습니다.
- 캐시 파일을 열거나 쓰지 못해도 분석은 그대로 진행합니다.

## 결과 표시

- 시세 결과(`analyze_price`)의 `data_status_item.data_source`: `api`, `cache`, `stale_cache`, `null` ([분석 결과 형식](../../docs/analysis-result.md) 참고)
- 주소 결과(`resolve_address`)는 저장본을 썼을 때 `notes`에 안내 문구를 남깁니다.

## 설정 (.env)

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `PUBLIC_API_CACHE` | 켬 | `off`이면 캐시를 쓰지 않습니다 |
| `PUBLIC_API_CACHE_PATH` | `data/local/public_api_cache.sqlite` | 캐시 파일 위치. `data/local/`은 .gitignore 대상이고 `backend/var/`와 겹치지 않습니다 |

## 사용 범위

- `cache`를 따로 넘기지 않고 실제 네트워크를 쓸 때(`session` 없음)만 기본 캐시를 씁니다. 그래서 backend/ 코드를 바꾸지 않아도 서버 분석에 적용됩니다.
- 테스트처럼 가짜 `session`을 넣으면 기본 캐시 파일을 건드리지 않습니다. 캐시를 시험하려면 `cache=SQLiteApiCache(":memory:")`를 넘깁니다.
- `cache=None`이면 캐시를 쓰지 않습니다.
- 캐시를 비우려면 캐시 파일을 지우면 됩니다.

## 테스트

저장소 루트에서 실행합니다. 실제 API는 부르지 않습니다.

```
python -m unittest discover -s document/api_cache/tests -v
```
